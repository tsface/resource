# ClickHouse Pipeline 任务调度机制

## 一、Pipeline 的三种执行形态

`QueryPipeline`（`src/QueryPipeline/QueryPipeline.h`）定义了三种形态：

| 形态 | 判断条件 | Executor | 典型场景 |
|------|---------|----------|---------|
| **pulling** | `output != nullptr` | `PullingPipelineExecutor` | SELECT 查询，从 pipeline 末尾逐 block 拉取结果 |
| **pushing** | `input != nullptr` | `PushingPipelineExecutor` | INSERT，向 pipeline 入口推送数据 |
| **completed** | 非 pulling 且非 pushing | `PipelineExecutor` | 内部完全封闭的 pipeline，直接运行到结束 |

```cpp
// QueryPipeline.h
bool pulling() const { return output != nullptr; }
bool pushing() const { return input != nullptr; }
bool completed() const { return initialized() && !pulling() && !pushing(); }
```

无论哪种形态，底层最终都委托给 `PipelineExecutor` 执行。以 `PullingPipelineExecutor` 为例：

```cpp
// src/Processors/Executors/PullingPipelineExecutor.cpp
bool PullingPipelineExecutor::pull(Block & block) {
    if (!executor) {
        executor = std::make_shared<PipelineExecutor>(pipeline.processors, ...);
    }
    // 核心：每次 pull 调用一次 executeStep
    if (!executor->executeStep(&has_data_flag))
        return false;
    chunk = pulling_format->getChunk();
    return true;
}
```

## 二、核心调度模型：prepare / work 二阶段

每个 `IProcessor` 的核心接口（`src/Processors/IProcessor.h`）：

```cpp
enum class Status : uint8_t {
    NeedData,       // 需要上游数据才能继续
    PortFull,       // 下游端口满了，推不出数据
    Finished,       // 全部完成
    Ready,          // 可以调用 work() 做同步计算
    Async,          // 需要异步等待（如网络 IO）
    ExpandPipeline, // 需要动态扩展 pipeline 图
};

// prepare：负责轻量调度决策（O(1)，不得阻塞）
virtual Status prepare(const PortNumbers & updated_input_ports,
                       const PortNumbers & updated_output_ports);

// work：负责重量计算（可并行，不得访问 ports）
virtual void work();
```

**prepare 是"调度决策"，work 是"实际干活"。**

## 三、PipelineExecutor 的核心调度循环

### 3.1 入口：execute() 和 executeStep()

```cpp
// src/Processors/Executors/PipelineExecutor.cpp
void PipelineExecutor::execute(size_t num_threads, bool concurrency_control) {
    executeImpl(num_threads, concurrency_control);
    finalizeExecution();  // 检查所有节点是否 Finished，否则抛 LOGICAL_ERROR
}

void PipelineExecutor::executeImpl(size_t num_threads, bool concurrency_control) {
    // 1. 构建图，初始化就绪队列
    initializeExecution(num_threads, concurrency_control);

    // 2. 多线程模式 / 单线程模式
    if (num_threads > 1) {
        spawnThreads();                // 启动线程（ConcurrencyControl 动态扩缩）
        tasks.processAsyncTasks();     // 主线程处理异步任务（epoll wait）
        pool->wait();                  // 等待所有线程结束
    } else {
        auto slot = cpu_slots->tryAcquire();
        executeSingleThread(0);
    }
}
```

### 3.2 每个工作线程的主循环：executeStepImpl()

```cpp
// PipelineExecutor.cpp
void PipelineExecutor::executeStepImpl(size_t thread_num, std::atomic_bool * yield_flag) {
    auto & context = tasks.getThreadContext(thread_num);

    while (!tasks.isFinished() && !yield) {
        // ── 阶段1：从全局任务队列获取待执行的 processor ──
        while (!tasks.isFinished() && !context.hasTask())
            tasks.tryGetTask(context);    // 没任务就阻塞等待（condvar）

        // ── 阶段2：执行 processor 的 work() ──
        while (context.hasTask() && !yield) {
            // (2a) 调用 processor->work()
            if (!context.executeTask())
                cancel(ExecutionStatus::Exception);

            if (tasks.isFinished()) break;
            if (!checkTimeLimitSoft()) break;

            // (2b) work() 后调用 updateNode（即 prepare()）
            Queue queue, async_queue;
            auto status = graph->updateNode(
                context.getProcessorID(), queue, async_queue);
            if (status == ExecutingGraph::UpdateNodeStatus::Exception)
                cancel(ExecutionStatus::Exception);

            // (2c) 将新就绪的节点 push 到全局队列
            if (status == ExecutingGraph::UpdateNodeStatus::Done)
                tasks.pushTasks(queue, async_queue, context);

            // (2d) 如果资源允许，动态扩容线程
            spawnThreads();
        }
    }
}
```

这是一个 **"取任务 → work → prepare → 产生新任务"** 的循环。

### 3.3 executeTask() 内部

```cpp
// src/Processors/Executors/ExecutionThreadContext.cpp
bool ExecutionThreadContext::executeTask() {
    // 调用 IProcessor::work()
    executeJob(node, read_progress_callback);
```

## 四、ExecutingGraph：调度的"大脑"

### 4.1 图结构

`ExecutingGraph`（`src/Processors/Executors/ExecutingGraph.h`）将 processors 转化为图：

```cpp
struct Node {
    IProcessor * processor;
    uint64_t processors_id;

    Edges direct_edges;    // 输出端口 → 下游输入端口（正向边）
    Edges back_edges;      // 输入端口 → 上游输出端口（反向边）

    ExecStatus status;     // Idle / Preparing / Executing / Finished / Async
    std::mutex status_mutex;

    IProcessor::PortNumbers updated_input_ports;   // 待处理的输入端口变化
    IProcessor::PortNumbers updated_output_ports;  // 待处理的输出端口变化
    // ... 用于 profiling 的计数器
};

struct Edge {
    uint64_t to;               // 目标 processor id
    bool backward;             // 是否反向边
    uint64_t input_port_number;
    uint64_t output_port_number;
    Port::UpdateInfo update_info;  // 端口版本号，用于检测变化
};
```

每个连接会创建两条边（直接边和反向边），形成双向可达的图，以便 prepare 能双向传播。

### 4.2 updateNode()：核心调度逻辑

```cpp
// src/Processors/Executors/ExecutingGraph.cpp
ExecutingGraph::UpdateNodeStatus ExecutingGraph::updateNode(
    uint64_t pid, Queue & queue, Queue & async_queue)
{
    std::stack<Edge *> updated_edges;
    std::stack<uint64_t> updated_processors;
    updated_processors.push(pid);

    while (!updated_processors.empty() || !updated_edges.empty()) {
        // ── 情况A：port 数据变化触发邻居 processor 需要被 prepare ──
        if (updated_processors.empty()) {
            auto * edge = updated_edges.top();
            updated_edges.pop();
            auto & node = *nodes[edge->to];

            if (node.status != ExecStatus::Finished) {
                // 记录端口变化
                if (edge->backward)
                    node.updated_output_ports.push_back(edge->output_port_number);
                else
                    node.updated_input_ports.push_back(edge->input_port_number);

                // 如果节点空闲，标记为 Preparing 加入待处理栈
                if (node.status == ExecStatus::Idle) {
                    node.status = ExecStatus::Preparing;
                    updated_processors.push(edge->to);
                } else
                    nodes[edge->to]->processor->onUpdatePorts();
            }
        }

        // ── 情况B：对 processor 执行 prepare() ──
        if (!updated_processors.empty()) {
            pid = updated_processors.top();
            updated_processors.pop();
            auto & node = *nodes[pid];

            // 核心：调用 IProcessor::prepare()
            IProcessor::Status status = processor.prepare(
                node.updated_input_ports, node.updated_output_ports);
            node.last_processor_status = status;

            node.updated_input_ports.clear();
            node.updated_output_ports.clear();

            switch (status) {
                case IProcessor::Status::NeedData:
                case IProcessor::Status::PortFull:
                    node.status = ExecStatus::Idle;    // 等待数据/空间变化
                    break;
                case IProcessor::Status::Finished:
                    node.status = ExecStatus::Finished; // 彻底结束
                    break;
                case IProcessor::Status::Ready:
                    node.status = ExecStatus::Executing;
                    queue.push(&node);                  // 放入就绪队列，等待 work()
                    break;
                case IProcessor::Status::Async:
                    node.status = ExecStatus::Executing;
                    async_queue.push(&node);            // 放入异步队列
                    break;
                case IProcessor::Status::ExpandPipeline:
                    // 动态扩展 pipeline 图
                    expandPipeline(updated_processors, pid);
                    updated_processors.push(pid);       // 扩张后重新 prepare
                    break;
            }

            // 将 port 状态变化沿边传播给邻居
            for (auto it = node.post_updated_output_ports.rbegin(); ...)
                updated_edges.push(edge);   // 通知下游
            for (auto it = node.post_updated_input_ports.rbegin(); ...)
                updated_edges.push(edge);   // 通知上游
        }
    }
}
```

### 4.3 事件传播机制：Port::UpdateInfo

每个 port 有一个版本号机制。当数据被 push/pop 时，版本号递增。`updateNode()` 通过比较版本号来决定是否触发邻居的 prepare。

```cpp
// src/Processors/Port.h
struct UpdateInfo {
    uint64_t version = 0;
    std::vector<void *> * update_list;  // 指向所属节点的 post_updated_*_ports
    void * id;

    void trigger() {
        ++version;
        if (update_list)
            update_list->push_back(id);  // 将自身加入更新列表
    }
};

// 端口连接时设置：
it->setUpdateInfo(&added_edge.update_info);
```

当 `work()` 向端口 push 数据、或从端口 pop 数据时，触发 `trigger()`，版本号递增并将自身加入更新列表。随后 `updateNode()` 检测到这些变化，传播给相邻节点。

## 五、初始化执行

```cpp
// ExecutingGraph.cpp
void ExecutingGraph::initializeExecution(Queue & queue, Queue & async_queue) {
    std::stack<uint64_t> stack;

    // 将所有没有输出 edges 的 processor（即 Sink 节点）加入栈
    for (uint64_t proc = 0; proc < num_processors; ++proc) {
        if (nodes[proc]->direct_edges.empty()) {  // 无输出 = Sink
            stack.push(proc);
            nodes[proc]->status = ExecStatus::Preparing;
        }
    }

    // 从 Sink 回溯，逐节点 prepare，一直传播到 Source
    while (!stack.empty()) {
        uint64_t proc = stack.top();
        stack.pop();
        updateNode(proc, queue, async_queue);
    }
}
```

**初始化时从 Sink 往 Source 方向 prepare。** 因为：

1. Sink（如 `PullingOutputFormat`）`prepare()` 返回 `PortFull`（下游缓冲区满→等待消费）或 `NeedData`
2. `NeedData` 沿边传播到上游 → 上游被 prepare → 上游也返回 `NeedData`
3. ... → 最终 Source 被 prepare → Source 返回 `Ready`
4. Source 被放入就绪队列 → 开始真正的数据流

## 六、多线程调度与任务队列

### 6.1 ExecutorTasks

```cpp
// src/Processors/Executors/ExecutorTasks.h
class ExecutorTasks {
    TaskQueue<ExecutingGraph::Node> task_queue;   // 就绪队列（Ready tasks）
    PollingQueue async_task_queue;                 // 异步队列（epoll fd）
    ThreadsQueue threads_queue;                    // 线程等待/唤醒管理
    std::atomic_bool finished = false;
};
```

- **`task_queue`**：存储 prepare 返回 `Ready` 的节点，工作线程从中 pop 任务
- **`async_task_queue`**：存储 prepare 返回 `Async` 的节点（如 `RemoteSource` 等待网络），主线程执行 `epoll_wait`
- **`tryGetTask()`**：线程空闲时，优先从 `task_queue` 取任务；为空则阻塞等待 condvar
- **`pushTasks()`**：`updateNode()` 后把新就绪节点 push 入队列，并 `tryWakeUpAnyOtherThreadWithTasks()` 唤醒其他线程

### 6.2 动态扩缩容：ConcurrencyControl

```cpp
// PipelineExecutor.cpp
void PipelineExecutor::initializeExecution(size_t num_threads, bool concurrency_control) {
    // 通过 ConcurrencyControl 分配 CPU slot
    size_t min_threads = concurrency_control ? 1uz : num_threads;
    cpu_slots = ConcurrencyControl::instance().allocate(min_threads, num_threads);
    use_threads = cpu_slots->grantedCount();
}

void PipelineExecutor::spawnThreads() {
    // 每次 work() 后尝试扩容：如果能获取到新的 cpu slot，就启动新线程
    while (auto slot = cpu_slots->tryAcquire()) {
        size_t thread_num = threads.fetch_add(1);
        tasks.upscale(thread_num + 1);
        pool->scheduleOrThrowOnError([this, thread_num, ...] {
            executeSingleThread(thread_num);
        });
    }
}
```

实现 **work-conserving 调度**：只要 CPU 有配额、有就绪任务，就启动新线程并行执行。

## 七、反压机制（Back Pressure）

反压通过 **PortFull / NeedData** 状态自然实现：

```
Source (Ready) → work() → push data → 下游 PortFull？

如果下游 PortFull：
  → Source prepare() 返回 PortFull
  → Source 状态设为 Idle（不再入队）
  → 等待下游消费后 port 状态变化
  → 事件传播回 Source → prepare() → Ready
  → 继续生产数据
```

这是一个天然的 **信用流控**：下游消费多少，上游就生产多少，不会有数据无限堆积。

## 八、完整调度流程示例

以一个典型的 pipeline 为例：

```
[BlocksListSource × 3] → [MergingSortedTransform] → [PullingOutputFormat]
```

**执行流程：**

```
1️⃣ initializeExecution：
   从 PullingOutputFormat (Sink，无输出) 开始 prepare
   → prepare() 返回 PortFull（下游未消费）
   → 状态设为 Idle，结束

2️⃣ 用户调用 PullingPipelineExecutor::pull()
   → 消费了 PullingOutputFormat 的输出
   → port 状态变化，触发 MergingSortedTransform 的 updated_input_ports

3️⃣ updateNode(MergingSortedTransform)：
   → prepare() 发现需要数据 → 返回 NeedData → 状态设为 Idle
   → 通过 back_edges 通知上游 3 个 BlocksListSource

4️⃣ updateNode(BlocksListSource × 3)：
   → prepare() 发现有数据可读 → 返回 Ready → 放入 task_queue

5️⃣ 线程取出 BlocksListSource：
   → work() 产出 Block，push 到 output port
   → 再次 prepare() → 还有数据？Ready / 没数据？Finished
   → port 数据变化通知 MergingSortedTransform

6️⃣ updateNode(MergingSortedTransform)：
   → input port 来了数据 → prepare()
   → 需要更多数据？NeedData / 可以合并？Ready
   → 如果 Ready，放入 task_queue

7️⃣ work(MergingSortedTransform)：
   → 从各 input port 读取，多路归并，产出结果 block
   → push 到 PullingOutputFormat
   → prepare() → 继续循环...

8️⃣ PullingOutputFormat 收到数据 → 返回 Ready
   → 如不消费则 PortFull → 反压上游
```

## 九、核心设计要点总结

| 设计要点 | 说明 |
|---------|------|
| **prepare/work 分离** | prepare 做轻量调度决策（O(1)），work 做重量计算（可并行） |
| **事件驱动** | 通过 port 版本号（UpdateInfo）追踪变化，精确触发邻居 prepare，避免轮询 |
| **DAG 双向传播** | 每条连接有正向边和反向边，prepare 可沿两个方向传播（NeedData 向上游，PortFull 向下游） |
| **work-conserving 多线程** | ConcurrencyControl 动态分配线程数，任务队列平衡负载 |
| **自然反压** | PortFull/NeedData 状态在 DAG 上自然形成流速控制 |
| **Sink 驱动初始化** | 从 Sink 开始反向回溯 prepare，建立完整的"拉取链" |
| **动态扩图** | ExpandPipeline 允许运行中动态添加 processor，适用于子查询等场景 |
| **async 支持** | Async 状态 + epoll fd 支持网络 IO 等异步操作无缝集成 |
